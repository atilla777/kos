# Интеграция KOS с OpenCode

После установки сервера и CLI пользователь может установить из репозитория KOS глобальные skills и профили OpenCode. Они доступны при работе в разных Git-репозиториях. Установка не изменяет существующие настройки моделей и не заменяет отличающиеся по содержимому файлы с теми же именами: о конфликте сообщается до копирования. После установки или обновления необходимо перезапустить OpenCode. Проверка наличия профилей и моделей описана в [README](../../../README.md).

## Выполнение задачи

Пользователь в режиме Build просит основного агента загрузить skill `kos-orchestrator` и задаёт уникальную постоянную идентичность сессии. Отдельного основного режима KOS нет; установленный ранее профиль `agent/kos-orchestrator.md` нужно удалить, чтобы он исчез из выбора режимов после перезапуска OpenCode. Оркестратор восстанавливает существующий действующий захват либо захватывает задачу и видит короткий маршрут текущего шага: позицию, исполнителя и, для субагента, уровень модели. Содержимое инструкций и документов в этот маршрут не включено.

Шаг `main` оркестратор выполняет сам. Для шага `subagent` уровня `standard` он привлекает профиль GPT-6 Luna, уровня `advanced` — GPT-6 Sol. Уровень выбирается автором workflow по сложности шага; простая разработка тоже может быть `standard`. Исполнитель получает ID задачи, проект, позицию шага и действующий claim, а инструкцию, входные документы и ожидаемые результаты запрашивает самостоятельно через CLI. Если вход отсутствует, исполнитель видит это явно и сообщает, если без него невозможно продолжить. Найденные документы содержат источник и версию.

Исполнитель сохраняет результат под действующим захватом всей задачи. Для создания отсутствующего документа и обновления существующей версии используются разные ожидания; конфликт версии не переписывает более свежий результат. Оркестратор проверяет работу и явно продвигает шаг с ожидаемой позицией либо завершает задачу на последнем шаге. Если правила проекта требуют публикации, её выполняет главный агент согласно этим правилам.

## Продолжение и ошибки

При долгой работе оркестратор явно продлевает lease. После его истечения старый claim больше не даёт права записи: агент проверяет текущую задачу и повторно захватывает её, если она доступна. Шаг и сохранённые результаты остаются на месте. Повторное продвижение с прежней позицией получает конфликт. При неопределённом исходе сетевого запроса исполнитель или оркестратор сначала проверяет состояние задачи либо документа, затем решает, нужен ли новый запрос. Никакой клиентский skill не гарантирует, что прерванный агент перестал менять внешние файлы.

Настройка моделей относится только к OpenCode. KOS не проверяет использованную модель, содержание выхода, прохождение тестов или факт публикации. Для исходного API и CLI шаги `standard` и `advanced` остаются независимыми от конкретного агентного harness.
