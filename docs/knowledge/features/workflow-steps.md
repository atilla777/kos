# Workflow и шаги задачи

Workflow — сохранённое определение последовательности шагов для одного проекта либо общее для всех проектов. Каждый шаг содержит инструкцию, способ выполнения (`main` или `subagent`), ожидаемые результаты и указания на входные артефакты. Шаг субагента также задаёт уровень модели: `standard` или `advanced`. Сопоставление уровня с конкретной моделью, вызов субагента и настройка harness выполняются вне сервера KOS. Для OpenCode доступна [отдельная интеграция](opencode-integration.md).

## Создание и назначение

Пользователь создаёт workflow проекта через CLI `kos workflow create --file workflow.json` либо JSON API. Создание такого workflow в новом проекте одновременно регистрирует проект. Команда `kos workflow create --global --file workflow.json` создаёт общее определение без регистрации проекта. Список workflow проекта содержит его собственные и общие определения; для ещё не зарегистрированного проекта — только общие, без автоматической регистрации. Определение можно просмотреть, но нельзя редактировать: для нового порядка или инструкции создаётся другое. Используемый задачами workflow удалить нельзя.

При создании задачи необходимо указать ID workflow её проекта или общего workflow. Проектный workflow другого проекта использовать нельзя. Её текущим шагом становится первый шаг (позиция `0`); тип задачи не выбирает workflow автоматически. После обновления с прежнего локального MVP старые задачи очищаются: ранее у них не было назначенного workflow или шага. Уже созданные проектные workflow и задачи с назначенным шагом остаются при переходе к общим workflow.

## Маршрут для оркестратора

Захват задачи с `--route` либо получение `current --route` возвращают компактные данные: ID задачи и workflow, позицию текущего шага, его название, `executor`, `model_tier` (если требуется) и собственный `claim_id`. Содержимое документов в этом ответе отсутствует. Без `--route` захват и `current` продолжают возвращать подробный контекст задачи. Истечение lease, release и повторный захват сохраняют текущий шаг.

Оркестратор решает, выполнить шаг самостоятельно или запустить субагента согласно маршруту. Субагент не захватывает задачу отдельно: сохранение результата требует действующего claim задачи. В интеграции OpenCode ему передаётся только отпечаток захвата и ID сессии, а CLI получает токен внутри процесса; другие клиенты могут передавать токен напрямую. Чтение инструкции и артефактов не требует claim. KOS не выбирает конкретную модель и не запускает агента.

## Пакет шага для исполнителя

`kos task step show TASK_ID` возвращает за один запрос инструкцию текущего шага, маршрут, ожидаемые ключи выходных документов и входы. Для каждого входа результат содержит селектор, найденные артефакты с содержимым, версией и исходной задачей либо `missing: true`, если совпадений нет. Вход из `task` ищется в текущей задаче; вход из `blockers` — в её непосредственных блокирующих задачах. Если совпали несколько блокеров, возвращаются все найденные документы с указанием источника. Далёкие предшественники не подтягиваются автоматически.

KOS не создаёт пустые входы и не требует выходные документы для продвижения. Сохранение результата производится существующей командой `task artifact put` с действующим claim и ожидаемой версией. Ответ пакета возвращает все совпадения; если входов много, он может быть объёмным. Для выборочного чтения доступны отдельные команды артефактов.

## Переход и ошибки

После проверки работы оркестратор вызывает `kos --claim CLAIM task advance TASK_ID --expected-step N`, указывая позицию, которую он получил ранее. Переход возможен только при действующем захвате и только до последнего шага. Повторный либо запоздавший запрос с прежней позицией получает `step_conflict`, не перескакивая через шаг; просроченный claim тоже не продвигает задачу. После повторного захвата новый исполнитель видит ту же позицию и сохранённые результаты.

На последнем шаге вместо `advance` задачу завершают обычной командой `task complete`. До последнего шага завершение отклоняется. Завершение означает утверждение исполнителя о готовности: KOS не проверяет содержание документов, выполнение инструкций, модель или качество работы.
