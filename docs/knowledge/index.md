# KOS — пользовательские возможности

Этот каталог — OKF bundle с актуальным описанием наблюдаемого поведения реализованных возможностей KOS. Он служит источником истины для пользовательских сценариев; [спецификация MVP](../mvp-specification.md) фиксирует исходные границы и базовый контракт. При расхождении сначала согласуйте изменение требований, затем приведите документы и реализацию в соответствие.

* [Работа с задачами](features/task-work.md) — создание, доступность, захват, продолжение, результаты и завершение задачи глазами пользователя.
* [Workflow и шаги задачи](features/workflow-steps.md) — маршрут для оркестратора, пакет исполнителя и продвижение шага.
* [Интеграция с OpenCode](features/opencode-integration.md) — установка skills, выбор модели и выполнение шагов через CLI.

## Как поддерживать документы

Для каждой новой или изменённой пользовательской возможности создавайте либо обновляйте тематический `.md` concept здесь и добавляйте ссылку в индекс. Формат: UTF-8 Markdown с YAML-frontmatter и непустым `type`; рекомендуются `title`, `description`, `tags`. Пишите ожидаемое поведение, сценарии, сообщения об ошибках и ограничения, а не код, таблицы БД и последовательность вызовов внутри приложения. Не приписывайте документу `verified: human:...` без фактического подтверждения человеком. Архивные task notes и артефакты конкретных задач не подменяют эти живые описания.

Формат: [Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md). Этот каталог является отдельным bundle: существующие технические файлы в `docs/` не обязаны соответствовать OKF.
